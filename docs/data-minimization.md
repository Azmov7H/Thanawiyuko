## 2. مبادئ التصميم لتقليل البيانات

1. **القيم الافتراضية الذكية:** الطالب يختار الصف/الشعبة مرة واحدة → المواد تُشتق من المنهج.
2. **السياق المجهول للذكاء الاصطناعي:** يُرسل للطلب السياق الدراسي والسؤال **بدون** اسم،
   بريد، أو معرّف جلسة.
3. **لا تخزين للبطاقات:** Paymob يعالج الدفع، ونخزّن `providerRef` + المبلغ + الحالة فقط.
4. **لا ملفات تعريف إعلانية:** لا Pixel، لا Analytics لجهات خارجية (تم التحقق: لا توجد أي إشارات).
5. **التحليلات مجهولة الهوية:** التقارير الداخلية تستخدم معرفات `studentId` أو إحصاءات مجمّعة.

## 3. تقليل البيانات في الكود (Code-Level Patterns)

```typescript
// ✅ جيد: نمرّر فقط ما يلزم
await runTutor({ userId, question, topicId });

// ❌ سيء: تمرير كائن المستخدم كاملاً
await runTutor({ user: fullUserObject, question });
```

```typescript
// ✅ جيد: استعلام مجهول للإحصاءات
const stats = await AttemptModel.aggregate([
  { $match: { userId: userObjectId } },
  { $group: { _id: null, avgAccuracy: { $avg: "$accuracy" } } },
]);

// ❌ سيء: جلب كل المحاولات مع البيانات الكاملة بلا داعٍ
const attempts = await AttemptModel.find({ userId });
```

> **درس مهم (T-H3):** عند استخدام `aggregate` يجب تحويل معرّف المستخدم النصي إلى
> `ObjectId` صراحةً (`new mongoose.Types.ObjectId(id)`)؛ لأن `$match` لا يطبّق تحويل
> المخطط كما تفعل `find()`.

## 4. قائمة مراجعة الميزة الجديدة (Feature Data Review Checklist)

قبل دمج أي ميزة جديدة، يجب الإجابة بنعم على كل بند:

- [ ] هل البيانات المجمعة **أقل مجموعة ممكنة** لتعمل الميزة؟
- [ ] هل هناك **قيمة افتراضية** تغني عن سؤال المستخدم؟
- [ ] هل البيانات **مجهولة الهوية** قبل إرسالها لجهة خارجية (AI، تحليلات)؟
- [ ] هل فترة الاحتفاظ **محددة ومبررة** في `docs/privacy-policy.md`؟
- [ ] هل يمكن للمستخدم **رؤية، تصدير، حذف** هذه البيانات؟ (`GAP` — غير منفّذ بعد، T-N2)
- [ ] هل الميزة تعمل **بدون** البيانات الاختيارية (Opt-in حقيقي)؟
- [ ] هل تم تحديث `docs/data-minimization.md` و `docs/privacy-policy.md`؟

## 5. المراجعة الدورية
- **شهريًا:** مراجعة السجلات للتأكد من عدم تسرب بيانات غير ضرورية.
- **ربع سنوي:** تحديث المصفوفة أعلاه، وحذف أي حقل لم يعد مستخدمًا.
- **سنويًا:** مراجعة خارجية لمبدأ تقليل البيانات (Privacy by Design Audit).
