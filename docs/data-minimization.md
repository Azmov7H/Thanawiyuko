# مبدأ تقليل البيانات — ثانويكو

**القاعدة الذهبية:** لا نجمع، نخزن، نعالج، نشارك، أو نحتفظ بأي بيان **إلا إذا كان ضرورياً تماماً** لتقديم الخدمة التعليمية الأساسية أو للامتثال القانوني.

## 2. مبادئ التصميم لتقليل البيانات

1. **القيم الافتراضية الذكية:** الطالب يختار الصف/الشعبة مرة واحدة → المواد والوحدات تُملأ تلقائياً من المنهج.
2. **السياق المجهول للذكاء الاصطناعي:** نرسل للسؤال: `الصف + الشعبة + خلاصة الدرس + السؤال` — **بدون** اسم، بريد، IP، معرف جلسة.
3. **لا تخزين للبطاقات:** Paymob يعالج الدفع، نحن نخزن `providerRef` + `المبلغ` + `الحالة` فقط.
4. **لا ملفات تعريف إعلانية:** لا Facebook Pixel، لا Google Analytics، لا ملفات تعريف تابعة لجهات خارجية.
5. **التحليلات مجهولة الهوية:** كل التقارير الداخلية تستخدم `studentId` مجهول (hash) أو إحصاءات مجمعة فقط.

## 3. تقليل البيانات في الكود (Code-Level Patterns)

```typescript
// ✅ جيد: نمرر فقط ما يلزم
await runTutorStream({
  userId,           // مطلوب للكوتا
  question,         // مطلوب للرد
  topicId,          // مطلوب للسياق
  // لا نمرر: email، name، ip، device، location
});

// ❌ سيء: تمرير كائن المستخدم كاملاً
await runTutorStream({ user: fullUserObject, question });
```

```typescript
// ✅ جيد: استعلام مجهول للإحصاءات
const stats = await AttemptModel.aggregate([
  { $match: { studentId: userId } },
  { $group: { _id: null, avgAccuracy: { $avg: "$accuracy" } } },
]);

// ❌ سيء: جلب كل المحاولات مع البيانات الكاملة
const attempts = await AttemptModel.find({ studentId: userId });
```

## 4. قائمة مراجعة الميزة الجديدة (Feature Data Review Checklist)

قبل دمج أي ميزة جديدة، يجب الإجابة بنعم على كل بند:

- [ ] هل البيانات المجمعة **أقل مجموعة ممكنة** لتعمل الميزة؟
- [ ] هل هناك **قيمة افتراضية** تغني عن سؤال المستخدم؟
- [ ] هل البيانات **مجهولة الهوية** قبل إرسالها لجهة خارجية (AI، تحليلات)؟
- [ ] هل فترة الاحتفاظ **محددة ومبررة** في `docs/privacy-policy.md`؟
- [ ] هل يمكن للمستخدم **رؤية، تصدير، حذف** هذه البيانات من الإعدادات؟
- [ ] هل الميزة تعمل **بدون** البيانات الاختيارية (Opt-in حقيقي)؟
- [ ] هل تم تحديث `docs/data-minimization.md` و `docs/privacy-policy.md`؟

## 4. المراجعة الدورية
- **شهريًا:** مراجعة السجلات للتأكد من عدم تسرب بيانات غير ضرورية.
- **ربع سنوي:** تحديث المصفوفة أعلاه، حذف أي حقل لم يعد مستخدمًا.
- **سنويًا:** مراجعة خارجية لمبدأ تقليل البيانات (Privacy by Design Audit).
